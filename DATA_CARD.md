# Data Card: Universe PR Drift Safety Study

This data card describes the artifacts in `ai-village-agents/pr-drift-safety-study`, a secondary exploratory dataset about pull-request drift during the AI Village “Connect your worlds into a 3D universe!” sprint.

## Dataset summary

- **Unit of analysis:** one GitHub pull request to `ai-village-agents/the-universe`.
- **Snapshot size:** 610 PRs.
- **Source:** public GitHub metadata, changed-file summaries, issue comments, and local git reconstruction from fetched PR heads.
- **Time period:** the Universe sprint trace captured in May 2026.
- **Primary use:** studying observable signals of stale branches, duplicate/superseded PRs, source-layout risk, rollback/replacement risk, and limits of green checks in high-velocity LLM-agent collaboration.
- **Status:** exploratory secondary research. Keyword labels are weak supervision; pilot manual labels are illustrative, not a complete adjudication.

## Key columns in `results/pr_level_features.csv`

### Metadata and outcomes

- `number`, `title`, `user`, `state`, `html_url`
- `created_at`, `updated_at`, `closed_at`, `merged_at`
- `merged`: `1` if GitHub reports a merge timestamp, else `0`.
- `closed_unmerged`: `1` if closed with no merge timestamp, else `0`.
- `open`: `1` for the single still-open PR in this snapshot.

### API changed-file features

- `files_changed`, `additions`, `deletions`, `changes`, `deletion_ratio`
- `touch_main_js`, `touch_config_js`, `touch_anchorage`, `touch_landmark`, `touch_validator`
- `added_files`, `modified_files`, `removed_files`, `filenames`

These come from the GitHub API file-summary endpoint and may differ from local git reconstruction for stale branches.

### Comment keyword features

Keyword flags are generated from issue comments by regular expressions. Important flags include:

- `kw_stale`
- `kw_rollback`
- `kw_sparse`
- `kw_post_array`
- `kw_duplicate`
- `kw_green_but_bad`
- `kw_not_merge_safe`
- `kw_merge_safe_positive`
- `risk_comment_label`: union of the negative/risk keyword flags.

These are **weak labels** over reviewer language, not final safety judgments.

### Title and timing features

- `title_cosmic_batch`, `title_landmark`, `title_fix`
- `slot_start`, `slot_end`, `slot_span` when a numeric slot range is parseable from the title.
- `created_hour_utc`, `created_date`
- `minutes_since_prev_merge`, `merges_prior_30m`, `prs_created_prior_30m`

### Local git reconstruction features

Generated by `analysis/add_git_metrics.py` after fetching PR refs into a local clone of `ai-village-agents/the-universe`.

- `git_base_exists`, `git_head_exists`, `git_merge_sha_exists`
- `git_merge_base_sha`
- `git_base_is_ancestor_of_head`, `git_merge_base_is_base`
- `git_commits_behind_base`, `git_commits_ahead_base`
- `git_files_changed`, `git_additions`, `git_deletions`, `git_changes`, `git_deletion_ratio`
- `git_touch_main_js`, `git_touch_config_js`, `git_touch_anchorage`, `git_touch_landmark`, `git_touch_validator`
- `git_added_files`, `git_modified_files`, `git_removed_files`, `git_renamed_or_copied_files`
- `git_filenames`

Optional cosmic-sight count columns are present but blank in the published fast run unless `analysis/add_git_metrics.py --count-cosmic` is used.

## Collection and reconstruction protocol

1. `scripts/collect_pr_metadata.py` collects public PR metadata.
2. `scripts/enrich_prs.py` collects changed-file summaries and issue comments.
3. The local Universe clone is prepared with:

   ```bash
   git clone https://github.com/ai-village-agents/the-universe.git /home/computeruse/the-universe
   cd /home/computeruse/the-universe
   git fetch origin '+refs/pull/*/head:refs/remotes/origin/pr/*' --prune
   ```

4. `analysis/add_git_metrics.py --universe-repo /home/computeruse/the-universe` reconstructs base/head git metrics.
5. `analysis/analyze_pr_drift.py` merges the metadata, API features, comments, timing features, and git features into `results/pr_level_features.csv` and regenerates `results/descriptive_report.md`.
6. `analysis/make_figures.py` regenerates the descriptive visual appendix from the published CSVs.
7. `analysis/validate_artifacts.py` checks the published row counts, required columns, report presence, and relative Markdown links.

## Known caveats

1. **Weak supervision:** keyword flags are only reviewer-language proxies. They mix true positives, false positives, and reviewer-attention effects.
2. **Merge outcome is not safety:** merged PRs can still have semantic issues, and closed PRs can be safe but superseded, late, or redundant.
3. **Git diff size is not a label:** high deletions and non-descendant heads are strong audit-priority signals, but manual inspection is needed before assigning rollback/source-integrity risk.
4. **API vs local git differences:** GitHub API file summaries and local `git diff base..head` can diverge for stale branches or reconstruction choices. The published report records both.
5. **Historical process dependence:** this trace reflects one sprint, one repository structure, and a specific group of LLM agents/reviewers.
6. **Comments are endogenous:** comments are partly caused by perceived risk and review intensity, so keyword-risk models partly predict reviewer attention rather than latent safety.
7. **Pilot labels are incomplete:** [`results/manual_validation_pilot.csv`](results/manual_validation_pilot.csv) demonstrates the manual protocol on 11 evidence-rich PRs; it is not a complete 79-PR validation.

## Recommended uses

- Audit and benchmark stale-branch triage heuristics for high-velocity collaborative repos.
- Compare API file summaries with local git reconstruction under PR drift.
- Develop manual-label protocols for rollback, source-integrity, and duplicate/superseded risks.
- Teach why green checks and mechanical mergeability are insufficient for semantic integration safety.

## Discouraged uses

- Treating `risk_comment_label` as ground truth.
- Ranking individual agents by skill or safety without controlling for assigned task type, review intensity, and timing.
- Deploying the descriptive models as production classifiers.
- Inferring general LLM-agent behavior from this one repository without replication.
