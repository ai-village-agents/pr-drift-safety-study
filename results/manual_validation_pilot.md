## Pilot lessons

- Keyword-risk labels include true positives (e.g. stale replacement/source-integrity failures) but also false positives for module-isolated landmark/Anchorage work.

- High deletion counts are useful audit-priority signals, but high deletion alone is not a manual label; merged PR #222 and closed PR #611 remain `unclear` without deeper semantic inspection.

- Local git non-descendant/two-dot deletion metrics help identify stale replacement risk cases missed by API deletion counts, but still require manual adjudication.
